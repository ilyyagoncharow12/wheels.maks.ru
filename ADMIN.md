# Админ-панель «Шины Макс»

Панель управления каталогом, текстами, оформлением сайта и журналом работ.
Работает локально на вашем компьютере и сохраняет изменения прямо в файлы проекта —
никаких баз данных и сторонних сервисов.

## Быстрый запуск (рекомендуемый)

Дважды щёлкните **`start-admin.bat`** в папке проекта. Откроется окно с заголовком
**«Wheels Max — admin server»** и браузер по адресу <http://localhost:8787/admin/>.

**Не закрывайте окно сервера** — пока оно открыто, панель работает. Закрытие окна
означает остановку сервера; чтобы войти снова, запустите батник ещё раз.

## Запуск из терминала (альтернатива)

Откройте PowerShell или «Командную строку» **в папке проекта** и выполните:

```powershell
cd C:\Users\5\PycharmProjects\wheels.maks.ru
npm run admin
```

То же самое без npm:

```powershell
node admin-server.mjs
```

Затем откройте <http://localhost:8787/admin/> в браузере. Остановить сервер — `Ctrl+C`
в окне терминала.

Другой порт, если 8787 занят:

```powershell
$env:PORT=8788; npm run admin
```

Для обычной «Командной строки» (cmd):

```bat
set PORT=8788 && node admin-server.mjs
```

Проверить, что сервер запущен, можно командой:

```powershell
(Invoke-WebRequest http://127.0.0.1:8787/api/session -UseBasicParsing).StatusCode
```

Должно вернуться `200`. Если запрос не проходит — сервер не запущен.

> Важно: панель работает **только на этом компьютере**. Сайт в интернете обновляется
> через кнопку «Опубликовать (git push)», но вход в панель всегда идёт через
> `http://localhost:8787/admin/` на вашем ПК.

## Если батник не запускается

1. **Проверьте Node.js:** в терминале `node --version`. Должно быть что-то вроде `v20…`.
   Если команда не найдена — скачайте и установите Node.js с <https://nodejs.org/>.
2. **Откройте адрес вручную:** <http://localhost:8787/admin/>. Батник только запускает
   сервер и браузер; если браузер не открылся сам, адрес можно ввести руками.
3. **Посмотрите окно «Wheels Max — admin server»:** там видны ошибки. Чаще всего это
   «порт 8787 занят» — значит сервер уже запущен, просто откройте адрес из пункта 2.
4. **Файл должен быть с переводами строк Windows (CRLF).** Это уже исправлено,
   а `.gitattributes` не даёт ему снова сломаться. Если вы редактировали `.bat`
   в редакторе, который сохраняет LF, проверьте, что переводы строк снова CRLF.
5. **Убедитесь, что запускаете файл из папки проекта.** Батник сам переходит
   в свою папку (`cd /d "%~dp0"`), но сам `admin-server.mjs` и `admin.config.json`
   должны лежать рядом с ним.
6. Если окно сервера было закрыто — панель не работает. Запустите батник заново.

## Аккаунты

| Аккаунт | Роль | Что доступно |
| --- | --- | --- |
| владелец (номер телефона) | `owner` | Всё: карточки шин, тексты, журнал работ, визуальный редактор, публикация, настройки. |
| `work` | `worker` | Только «Журнал работ» и «Настройки» (смена своего пароля). |

- Пароли не отображаются на странице входа и не хранятся в открытом виде:
  в `admin.config.json` лежат только соль и scrypt-хеш.
- Сменить свой пароль может любой аккаунт: **Настройки → Смена пароля**.
- **Одновременно работать может только один человек.** Новый вход завершает
  все предыдущие сессии, поэтому на втором устройстве вас разлогинит.
- Пока пароль остаётся выданным «по умолчанию», в панели висит предупреждение —
  смените его после первого входа.

## Что можно делать

| Раздел | Возможности |
| --- | --- |
| **Карточки шин** | Добавлять, редактировать и удалять товары. Менять бренд, модель, размер, сезон, состояние, протектор, год, цену, наличие, описание и ссылку на Авито. |
| **Порядок** | Перетаскивание карточек мышью (за «ручку» ⋮⋮) или стрелки ↑ ↓. Такой же порядок будет в каталоге на сайте (сортировка «Порядок из админки»). |
| **Фото** | Кнопка «Загрузить фото», перетаскивание файла в окно карточки или вставка ссылки. Загруженные файлы попадают в `images/uploads/`. |
| **Дублирование** | Кнопка-копия создаёт дубль карточки — удобно для похожих позиций. |
| **Тексты сайта** | 68 редактируемых полей: заголовки, описания, цифры, карточки «Почему мы», услуги, шаги, адрес, контакты, подвал. Можно использовать простой HTML. |
| **Журнал работ** | Учёт по машинам: дата, гос номер, марка, что сделали, фото машины, строка «что продали / работы» и полученная сумма. Есть поиск, фильтры по месяцу и году, итоги по выручке и машинам, группировка по месяцам. |
| **Визуальный редактор** | Страница сайта открывается прямо в панели. Клик по любому элементу — справа настройки: текст, ссылка, размер и цвет шрифта, фон, выравнивание, скругление, отступы. Можно скрыть элемент, дублировать его, добавить новый блок (заголовок, текст, кнопка, карточка) и отменить последнее действие. |
| **Настройки** | Смена пароля, публикация на сайт, открытие папки проекта, памятка по файлам. |

Кнопка **«Вернуть сохранённое»** в текстах отменяет несохранённые правки,
а ссылка **«сбросить»** у поля возвращает исходный текст из HTML.

### Журнал работ

Раздел открыт и владельцу, и мастеру. Запись содержит:

- **Дата** — выбирается в календаре; месяц, день, год и день недели показываются в списке.
- **Гос номер** и **марка/модель машины**.
- **Что сделано** — свободный текст, например «зачистка, герметик, балансировка».
- **Фотографии машины** — несколько файлов сразу, до 12 МБ каждый.
- **Что продали и какие работы сделали** — свободная строка, например
  «комплект шин 205/55 R16, герметик».
- **Получено, ₽** — сумма по записи.

Сверху считаются количество записей, число машин, общая выручка и количество фото.

### Визуальный редактор

- Правки применяются к выбранной странице: «Главная» или «Каталог шин».
- Карточки товаров и пагинация в редакторе не редактируются — они меняются
  в разделе «Карточки шин», чтобы не сломать каталог и синхронизацию с Авито.
- Правки хранятся отдельно от HTML (`site-edits.json`) и применяются на сайте
  при загрузке страницы. Это значит, что обновления каталога и скрапера их не стирают.
- После правок нажмите **«Сохранить правки»** и обновите сайт.
- Скрытые элементы остаются в разметке (класс `ve-is-hidden`), чтобы адреса
  элементов не смещались; добавленные блоки помечены `data-ve="…"`.

## Публикация

Сайт статический и размещён на GitHub Pages, поэтому изменения нужно отправить в репозиторий:

1. Раздел **Настройки** → поле «Сообщение коммита» (необязательно).
2. Кнопка **«Опубликовать (git push)»**.
3. Дождитесь сообщения «Готово — изменения отправлены в GitHub», затем обновите сайт.

Кнопка публикации доступна только владельцу.

Публикация использует установленный Git и ваши сохранённые учётные данные GitHub.
Если `git push` просит логин — один раз выполните в терминале проекта:

```bash
git push
```

и авторизуйтесь. Дальше кнопка будет работать без вопросов.

До публикации изменения видны только на локальном сервере (`http://localhost:8787/`).

## Где что хранится

| Файл / папка | Назначение |
| --- | --- |
| `products.js` | Все карточки товаров. Порядок в массиве = порядок на сайте. |
| `content.json` | Тексты, изменённые в панели. Пустое значение = текст по умолчанию из HTML. |
| `site-edits.json` | Правки визуального редактора: тексты, стили, атрибуты, скрытые и добавленные блоки. |
| `work-log.json` | Записи журнала работ. **Не публикуется** (в `.gitignore`). |
| `images/work/` | Фотографии машин из журнала. **Не публикуется**, отдаются только после входа. |
| `images/uploads/` | Загруженные фотографии товаров. |
| `admin.config.json` | Аккаунты (соль, scrypt-хеш, роль) и секрет сессий. **Не публикуется** (в `.gitignore`). |
| `.admin-backups/` | Автоматические резервные копии `products.js` перед каждым сохранением (последние 20). |

Все изменения сохраняются сразу при нажатии кнопок — отдельная «кнопка сохранить»
для карточек не нужна. У текстов и у визуального редактора есть свои кнопки сохранения.

## Синхронизация с Авито

Скрипт `scrape_avito.mjs` (команды `npm run sync`, `npm run watch`) по-прежнему обновляет
`products.js`. Учтите: при синхронизации он перезаписывает файл в своём формате,
поэтому заголовок-комментарий и порядок товаров могут измениться. Правки, сделанные
в админке, при этом сохраняются по ссылке на объявление — скрапер обновляет данные
существующих позиций, а не удаляет их.

Перед синхронизацией можно сделать резервную копию: панель уже складывает их
в `.admin-backups/` при каждом сохранении.

## Безопасность

- Сервер слушает только `127.0.0.1` — из интернета панель недоступна.
- Пароли хранятся как scrypt-хеши. Вход защищён подписанной сессионной cookie
  `HttpOnly` + `SameSite=Strict`; после 5 неудачных попыток вход блокируется на минуту.
- В каждый момент активна только одна сессия: новый вход завершает предыдущую.
- Мастер ограничен на сервере: ему доступны только `/api/work*`, `/api/password`,
  `/api/logout` и `/api/session`. Каталог, тексты, редактор, загрузка файлов
  и публикация требуют роль владельца.
- `work-log.json` и `images/work/` закрыты и напрямую через сайт не отдаются —
  фотографии журнала видны только после входа.
- Не выкладывайте `admin.config.json`, `work-log.json` и `images/work/` в открытый
  репозиторий — они уже исключены в `.gitignore`.
- Если планируете открывать панель с других устройств, сначала смените пароли
  и настройте доступ через VPN или SSH-туннель.

## Если что-то не работает

- **«Сервер недоступен»** — закройте страницу, запустите `start-admin.bat` и откройте адрес заново.
- **Порт занят** — запустите на другом порту: `set PORT=8788 && node admin-server.mjs`.
- **Не сохраняется фото** — поддерживаются PNG, JPG, WEBP, AVIF, GIF до 12 МБ.
- **Сайт не обновился после публикации** — GitHub Pages обновляется 1–2 минуты,
  проверьте вкладку Actions в репозитории.
